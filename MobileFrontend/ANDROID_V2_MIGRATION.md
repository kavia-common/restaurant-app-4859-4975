Android v2 embedding migration

What changed in this migration:
- Regenerated full Flutter project structure via: `flutter create -t app .`
- Adopted Kotlin DSL Gradle files (build.gradle.kts and settings.gradle.kts).
- Ensured MainActivity uses Android v2 embedding (extends FlutterActivity).
- Removed legacy Android v1 embedding artifacts:
  - Deleted old android/build.gradle, android/settings.gradle, android/app/build.gradle
  - Deleted legacy android/app/src/main/AndroidManifest.xml
  - Removed GeneratedPluginRegistrant.java from source control (this is auto-generated by Flutter tools).
- Kept existing Dart sources in `lib/`, test, assets, analysis options, and pubspec.yaml.
- New iOS/macOS/Linux/Windows/web scaffolding was generated by Flutter.

How to build (Android):
1) Ensure `android/local.properties` has a valid Flutter SDK path (flutter.sdk).
2) Clean and fetch:
   flutter clean
   flutter pub get
3) Analyze (optional):
   flutter analyze
4) Build APK:
   flutter build apk

Notes:
- The project now uses `android/settings.gradle.kts` and `android/app/build.gradle.kts`. Do not reintroduce Groovy build.gradle files.
- Plugins (shared_preferences, sqflite, url_launcher, etc.) register automatically with v2 embedding.
- If you see "unsupported Gradle project" errors, verify there are no leftover Groovy build.gradle/settings.gradle files or v1 embedding sources under android/.
- If you need to customize applicationId, min/target SDK, or signing, edit android/app/build.gradle.kts accordingly.

Troubleshooting:
- If Android build still reports v1 embedding usage, search the tree for:
  - io.flutter.app.FlutterActivity
  - io.flutter.app.FlutterApplication
  - GeneratedPluginRegistrant
  and remove any manually committed sources. Only keep the v2 `MainActivity : FlutterActivity`.
- Ensure only one pair of Gradle settings exists (the .kts files). Delete old duplicates in Groovy.

Plugins:
- Plugins auto-register with v2 embedding; no manual registrant is needed.
